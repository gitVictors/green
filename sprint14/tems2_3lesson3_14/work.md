# Задание
Разработайте шаблон класса Optional, который ведёт себя аналогично std::optional и хранит либо элемент, либо метку об отсутствии элемента.

Сохраните решение задачи на GitHub — оно вам ещё понадобится.
Класс Optional, в отличие от std::unique_ptr, должен хранить данные на стеке, а не в динамической памяти. Такие данные нужно инициализировать только при необходимости — по умолчанию Optional создаётся пустым. Для этого используйте размещающий оператор new. 
Чтобы корректно обработать основные этапы жизненного цикла Optional, перегрузите соответствующие конструкторы, операторы присваивания и деструктор. Сырая память будет удалена автоматически, но перед этим нужно вручную вызвать деструктор типа, который хранится в Optional.

# Требования к решению
Старайтесь не создавать лишний раз объекты типа T. Например, когда будете присваивать новый объект уже заполненному Optional, просто вызовите соответствующий оператор присваивания для типа T.

# Как будет тестироваться ваш код
Работа класса Optional проверится тестами, подобными тем, которые даны в заготовке кода. Функция main будет заменена версией из тренажёра.

# Что отправлять на проверку
В заголовочном файле optional.h должен быть исходный код класса Optional и класса BadOptionalAccess.

# Подсказка
Чтобы вовремя обнаружить ошибки работы с сырой памятью, используйте инструменты clang-tidy и UB sanitizer.
В операциях копирующего и перемещающего присваивания Optional = Optional обработайте четыре возможные ситуации: когда левый и правый аргументы операции присваивания могут быть как пустым, так и непустым Optional.
В операциях присваивания значения типа T обработайте две возможные ситуации: присваивание пустому и непустому Optional.
